## Routing And Load Balancing

- Attempt trail logging, from Bifrost: implemented for shared proxy routes. Each upstream attempt records backend/node, retry index, status, retryability, outcome, duration, and sanitized error text. The data is persisted in `request_attempts` when metadata logging is enabled and is exposed from `/admin/logs/{id}` as `attempt_trail` and `attempts`, so fallback and retry behavior can be audited without debug logs. Follow-up work remains for richer UI visualizations over attempt trails.

- Quota-aware backend selection, from Envoy AI Gateway: implemented as disabled-by-default backend token-quota peeking before routing. When enabled, exhausted candidates are skipped if an alternative has estimated capacity; if every candidate is exhausted, the full route is kept so existing upstream failure surfaces remain possible. Backend quota restore from log metadata is also available as a separate disabled-by-default toggle. Follow-up work remains for shared multi-replica backend quota state and upstream 429 learning.

- Adaptive load balancing, from Bifrost and Gateway API Inference Extension: route using live latency, queue depth, KV-cache utilization, health, and historical success signals rather than only static weights. Start as score-aware routing extensions because the Go router already has health scoring, half-open recovery, weighted round-robin, prefix-cache affinity, and disabled-by-default least-in-flight selection.

- Prefix-cache-aware scheduling, from Gateway API Inference Extension: implemented as disabled-by-default prefix-cache-affinity node scheduling under `router_settings.prefix_cache_affinity.enabled`. The router hashes shallow message prefixes (message 0, messages 0-1, messages 0-2) and records bounded in-memory `(node, prefix-hash)` bindings after successful `200` upstream responses. During node-pool selection it prefers the node bound to the longest matching prefix among nodes already eligible by endpoint support, node/app-key `allowed_keys`, health and half-open state, backend-availability, and quota-aware predicates. Sticky routing from `conversation_id`/`thread_id`/`previous_response_id` always takes precedence, and routing is byte-for-byte identical when disabled, when no prefix matches, or when every matching node is otherwise ineligible. Bindings are bounded by `max_entries` (default `4096`, FIFO eviction), in-memory only, and covered by race-friendly concurrent selection/recording tests.

Current node-pool routing order for fresh requests is:

1. Honor sticky conversation/thread/response routing when present.
2. If enabled, prefer the eligible node with the longest matching prefix-cache-affinity binding.
3. If enabled, prefer the eligible node with the fewest live in-flight upstream attempts.
4. Fall back to existing weighted or round-robin ordering after endpoint, app-key/node, health, half-open, backend-availability, and quota-aware eligibility gates.

- Centralized flow-control queues, from Gateway API Inference Extension: keep overflow in gateway-level priority/fairness queues instead of pushing every request into backend queues. This helps avoid priority inversion, noisy-neighbor behavior, and premature routing to saturated model servers.

- Model catalog and provider availability sync, from Bifrost: implemented as a read-only admin catalog with disabled-by-default, node/provider opt-in `/v1/models` probes plus a React Catalog tab and bounded read-only validation warnings derived from the redacted catalog snapshot. Probe results are TTL/backoff managed, expose only bucketed errors, and do not change routing. Follow-up work remains for UI selectors and any future routing use.

## Logging, Metrics, And Monitoring

- Prometheus `/metrics`, from Bifrost, TensorZero, Envoy AI Gateway, and Gateway API Inference Extension: implemented as a guarded snapshot endpoint for admission, quota, backend admission, backend quota, backend health state, backend in-flight request gauges, and disabled-by-default OTel-independent request/backend/stream timing histograms for request duration, backend attempt duration, TTFT, and aggregate TPOT. Follow-up work remains for richer per-phase counters and dashboards.

- OpenTelemetry traces, metrics, and span-event logs, from Bifrost, TensorZero, and Envoy AI Gateway: implemented as disabled-by-default OTLP gRPC request tracing plus request count/duration, reconciled GenAI token usage, stream TTFT, stream aggregate TPOT/ITL metrics, and optional sanitized `proxy.log` span events for generic JSON proxy, Messages, and Responses request, policy, admission, routing, upstream-attempt, response, parser, and logging phases where those phases run, plus direct passthrough request, upstream-attempt, and response phases. Config uses strict `proxy_settings.otel` validation, `proxy_settings.otel.logs.enabled` requires global OTel, bounded shutdown, and safe attributes for phase, endpoint kind, configured model label, backend name, key-scope bucket, retry/attempt indexes, stream flag, status, outcome, error bucket, token type/counts, trace/span IDs, and GenAI-style system/operation/model attributes. Persisted request metadata and `/admin/logs` rows can expose proxy-owned `trace_id` and `span_id` when OTel is enabled; admin-protected trace navigation can filter `/admin/logs?trace_id=...` and aggregate metadata through `/admin/traces/{trace_id}`, and the React Traces tab renders that sanitized metadata without full-request sidecars. Disabled/noop OTel leaves trace fields empty/omitted and does not start exporters or emit span-event logs. Follow-up work remains for deeper admin dashboard visibility beyond the current trace metadata view.

- Async log pipeline with content toggles, from Bifrost: separate metadata logging from request/response content logging, with the ability to disable content capture while keeping latency, cost, token, retry, and outcome data. This helps operate the proxy in privacy-sensitive environments.

- Admin dashboards for live operations, from Bifrost and Gateway API Inference Extension: first-pass React admin observability now surfaces exact-cache counters, backend health, usage/quota summaries, and admin-protected backend quota snapshots, while the read-only Traces tab surfaces sanitized trace summaries, timelines, attempts, retries, linked categorical errors, and token/timing metadata. Follow-up panels remain for queue size, quota burn-down, SLO violations, per-model cost, and deeper metrics.

- pprof/debug profiling endpoints, from Gateway API Inference Extension: expose guarded Go runtime profiles for heap/goroutine troubleshooting. This is low product surface but useful for diagnosing proxy memory growth or stream leaks.

## Endpoint Translation And Compatibility

- Pluggable translator interface, from Envoy AI Gateway: define per-endpoint translators with request body, response headers, response body, and error body hooks. yaLLMproxy already has translators, but a stricter interface would make adding providers and endpoints less ad hoc.

- Header and body mutation policies, from Envoy AI Gateway: declaratively remove/set headers and JSON body fields before upstream calls, with retry-safe restoration of original state. This overlaps with forced/default parameters but would generalize request shaping.

- Direct provider API-key override, from Bifrost: optionally allow trusted callers to provide an upstream provider key in a request header for controlled bypass or migration flows. This should be gated by admin policy because it changes the trust model.

- Provider-specific error normalization, from Envoy AI Gateway and Bifrost: translate backend errors into a stable client-facing shape while preserving enough upstream detail in logs. GigaChat upstream errors now preserve the established JSON error shape for non-stream calls and use SSE `data:` error events for stream calls. Broader provider-normalization parity remains follow-up work.

- Built-in Jinja-compatible template parser/analyzer, from Python yaLLMproxy and TensorZero's template-driven variants: parse or render chat templates enough to infer think tags, tool-call formats, prompt boundaries, and special generation prompts. Go now has a bounded inspection renderer/analyzer for admin/template inspection and parser-config derivation, including Qwen XML marker evidence. Full runtime Jinja compatibility, macros, and broad filter parity remain follow-up work.

- Template management APIs, from Python yaLLMproxy: restored for list/upload/inspect endpoints under `configs/jinja_templates` with path safety and admin protection. Inspect exposes detected parser fields, evidence, warnings, `tool_parser: qwen_xml` for marker-based Qwen-style templates, and bounded Jinja inspection metadata. Follow-up work remains for a full runtime Jinja renderer.

- Streaming JSON repair module, from Bifrost JSON parser plugin: implemented as an opt-in response module for streamed OpenAI-compatible tool/function argument fragments. It is disabled by default, bounded by `max_stream_buffer_bytes`, passes normal streams and valid JSON unchanged, and defaults to passthrough when repair is uncertain. Follow-up work remains for request-scoped enablement and non-tool structured content contexts such as selected `response_format: json_object` streams.

- Raw-vs-parsed response sidecars, from Python yaLLMproxy: non-stream JSON responses transformed by response modules now store raw upstream and transformed client bodies under the full-request sidecar `parsed_response` field when `full_request_storage.enabled`, `log_to_disk`, and `log_parsed_response` are all strictly true. Streaming/SSE responses can also store capped raw-upstream and transformed-client sidecar files under `parsed_stream` when `full_request_storage.enabled`, `log_to_disk`, and `log_parsed_stream` are all strictly true.

- Parser plugin lifecycle and cleanup, from Bifrost plugins: stream parser state now has configurable `max_stream_buffer_bytes` and `max_stream_buffer_age_seconds` bounds that flush over-limit or over-age parser buffers to literal content/reasoning instead of dropping text, streamed JSON repair releases over-age pending arguments unchanged, explicit reset/close lifecycle hooks clear per-stream state idempotently, and the write-only dropped-content accumulator has been removed. Follow-up work remains for full runtime Jinja renderer parity beyond bounded inspection.

Basic non-stream and stream translation is implemented, including detailed usage parity for cached input token and reasoning output token details mapped from Chat Completions usage, reasoning output items/events from OpenAI-compatible `reasoning_content`, non-stream terminal status mapping for `finish_reason: length` to `status: incomplete` with `incomplete_details` and `content_filter` to `failed`, Responses `tool_choice` normalization for required/any/specific tools, `service_tier` and `prompt_cache_key` pass-through, safe error `param` shape, image content mapping, and deterministic regression coverage for refusal/annotations including URL/file citation and file-path variants, empty content, streamed incomplete details, Anthropic content block ordering, text/tool interleaving, stop-reason/cache-usage deltas, and malformed/unknown SSE payloads. ## Governance, Auth, And Quotas

- Admin app-key CRUD, from Python yaLLMproxy and Bifrost virtual keys: implemented for create/update/delete/regenerate/list/config workflows with secret masking, admin password protection, and React admin controls that reveal create/regenerate secrets only once. Follow-up work remains for broader runtime config transaction cleanup.

- Hierarchical budgets and limits, from Bifrost: support budget/rate-limit scopes such as key, group, team/customer, provider config, and model. Go has per-key/group quotas, but hierarchical cost budgets would make multi-tenant operations cleaner.

- Required header policy, from Bifrost governance: implemented for global/group/key app-key rules with optional model scoping. Missing headers are rejected before admission/quota/upstream, optional `log_as` values are captured in full-request sidecar logs for accepted requests, and metrics expose only a bounded total counter.

- Provider-key allowlists per app key, from Bifrost virtual keys: restrict a client key to specific upstream provider keys or nodes, not just models. This is useful when customers have dedicated paid capacity or compliance-isolated credentials.

- Calendar-aligned quota resets, from Bifrost budgets: implemented for token quotas through `limits.token_quota_reset_mode` with daily, weekly, monthly, and yearly UTC boundaries while preserving rolling windows as the default.

- Provider/node/client-model backend CRUD APIs: implemented for `/admin/providers`, `/admin/nodes`, and `/admin/client-models` with admin-password write protection, raw config preservation, secret masking/preservation, dependency-aware deletes, fallback cleanup for deleted client models, and atomic validate/apply runtime swaps.

- Config transaction validation, from Envoy AI Gateway CRD status patterns: validate config changes and return field-level issues before applying runtime state. Go already has validation endpoints; expanding status/detail coverage would make admin changes safer.

## Caching

- Exact inference cache, from TensorZero: implemented as a disabled-by-default router-owned exact cache for identical non-stream `/v1/chat/completions`, `/v1/embeddings`, and translated non-stream `/v1/messages` or `/v1/responses` requests, with read/write, read-only, write-only, and off cache modes plus TTL, max-age, max-entry, max-entry-byte bounds, a truthy `x-yallmp-cache-bypass` request header that skips read/write and is stripped upstream, optional disabled-by-default SQLite persistence for client-facing response bytes, and admin-protected read-only `GET /admin/cache` counters for hits, misses, writes, evictions, entry count, entry bytes, and persistence counts. Translated endpoint entries store only complete 200 client-facing JSON responses, not upstream Chat Completions payloads. Follow-up work remains for streaming and native provider pass-through caching.

- Semantic cache, from Bifrost: implemented as disabled-by-default semantic recall for non-stream `/v1/chat/completions` behind `proxy_settings.inference_cache.semantic.enabled`. Enabling requires the global inference cache mode plus explicit embedding node/model config; lookup/store embeds the canonical outbound request body, stores embeddings and complete 200 client-facing JSON responses in a bounded in-memory index, filters by endpoint/raw query/backend/client model/embedding model/app-key/group/required-header scope/non-message controls before cosine ranking, and uses the same `x-yallmp-cache-bypass` read/write escape hatch. It is intentionally less transparent than exact caching, so persistence, translated endpoints, streaming, and per-model threshold policy remain follow-up work.

- Prompt-cache awareness, from Bifrost, TensorZero, and Gateway API Inference Extension: track cached-token usage from providers and use cache hit potential in routing. This pairs naturally with original/request/response model tracking and prefix-cache-aware scheduling.

## Persistence And Deployment

- PostgreSQL log store, from Python yaLLMproxy and TensorZero: implemented with `pgx/v5` through `database/sql` for request metadata, attempt trails, error logs, response state, quotas, and larger multi-host deployments. SQLite remains the local default; live PostgreSQL integration is gated by `YALLMP_TEST_POSTGRES_DSN`.

- HA state synchronization, from Bifrost enterprise notes: if running multiple Go proxy replicas, shared quotas, response-state stickiness, budget usage, and config reloads need a distributed state strategy. A Postgres-backed first pass may be enough before any consensus layer.

- Autoscaling signals, from Gateway API Inference Extension: expose queue size, queue duration, saturation, and SLO metrics that can drive HPA/KEDA-like autoscaling. Even outside Kubernetes, these are useful operational signals.

- Provider conformance test matrix, from Bifrost and Envoy AI Gateway: deterministic fake-local coverage exists for chat, Messages, and Responses pass-through and translated paths, plus endpoint-denied behavior. Fake smoke now covers daily quota reset visibility, translated Messages/Responses streaming tool and terminal edge behavior, direct passthrough fidelity, embeddings/rerank model rewrite assertions, and in-memory OTel span emission. Follow-up work remains for real-provider live conformance, structured outputs beyond tool arguments, images/audio if added, and broader passthrough fidelity alongside every new endpoint/provider feature.

- Fake client/fake upstream testing: implemented as `cmd/yallmp-smoke --mode=fake` and exposed through `task smoke:fake`. It starts an emulated upstream, the Go proxy handler, and a real HTTP client in-process, then verifies forwarding, routing, translation, logging, observability, cache, and parser behavior without leaving a persistent server. Follow-up work remains for latency/SLO measurements such as proxy-layer p95 overhead and for expanding the real-provider conformance matrix around newly added protocol surfaces.
